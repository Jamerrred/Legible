## Agent profiles to imitate

1. Index reader (search-API style). Never touches the site live in most cases; answers come from a cached copy of the page. Imitate: serve the stand-in a stored snapshot of the page text, with a configurable age. Behaviours to model: stale prices/hours, pages missing from the index, robots.txt opt-out meaning "absent". Sources: OAI-SearchBot, PerplexityBot, Exa cached, Claude web search.
2. Plain fetcher. One HTTP GET, HTML to text, no JS, no clicks, no forms, truncation by size, robots.txt may block (Claude web fetch is the clearest STATED case; Tavily basic, Exa live crawl and ChatGPT-User/Perplexity-User are probably similar, INFERENCE). Imitate: GET, strip to text or markdown, cap tokens, follow links only if found in the text. Key failure: content rendered by JS or hidden behind a booking widget is simply invisible.
3. Browser agent. A real Chromium session that renders JS, reads the page via DOM/accessibility tree or screenshots, clicks and fills forms, may stop for user confirmation. Sources: Comet, Manus, Claude browser use, ChatGPT agent (details UNVERIFIED). Imitate: Playwright plus an LLM loop with a step budget and a "ask the user before submitting" rule. Failure points: CAPTCHAs, login walls, date pickers, iframes, cookie banners.

Optional variant, not a fourth profile: Index reader plus fetcher in one loop (search, pick a URL, fetch, answer). This is how Claude's search-and-fetch pair is documented to work and is the most common default, so the stand-in should run profile 1 then 2 before 3.

## How evaluations work

What each source states (I read abstracts or summaries only; no full papers):
- WebArena: self-contained realistic sites in e-commerce, forums, code hosting and content management; scored by functional correctness of the outcome; best GPT-4 agent 14.41% vs humans 78.24% (STATED, [abstract](https://arxiv.org/abs/2307.13854)). Task count and failure analysis not on the page I read.
- WebVoyager: tasks on 15 real, live websites; GPT-4V auto-judge agrees with humans 85.3% of the time; agent 59.1% (STATED, [abstract](https://arxiv.org/abs/2401.13919)). Error categories not on that page.
- Online-Mind2Web: 300 tasks across 136 live sites; authors say earlier results were over-optimistic and propose an LLM judge at about 85% human agreement (STATED, [abstract](https://arxiv.org/abs/2504.01382)). Browser Use reports 83 easy / 143 medium / 74 hard tasks and a self-reported 97% with its own judge; it says a few tasks failed because sites were unavailable, prompts were ambiguous or sites had changed, and that small tweaks get "lost in run-to-run variance". It gives no run count or confidence interval and no failure taxonomy (STATED by a vendor, [Browser Use](https://browser-use.com/posts/online-mind2web-benchmark)). It also calls OpenAI's 93% unverifiable because the judge and task-level results are unpublished.
- BrowseComp: 1,266 questions (after 21 bad ones were removed, SECONDARY) with short single answers that are easy to check but hard to find; filtered so earlier models and humans (10 minutes) could not solve them (SECONDARY search summary; OpenAI's page returned 403). Original scores: Deep Research 51.5%, GPT-4o 0.6%. I could not confirm the "inverted question" construction.
- DeepResearch Bench: 100 expert-written PhD-level tasks in 22 fields; one method scores report quality against a reference with adaptive criteria, another counts effective citations and citation accuracy; both claim strong alignment with human judgment (STATED, [abstract](https://arxiv.org/abs/2506.11763)). Metric names (RACE, FACT) not on the page I read.
- Anthropic guidance: start with 20-50 tasks from real failures; a good task is one where two experts reach the same verdict; write a reference solution per task; grade outcomes not step sequences; mix code, model and human graders; give LLM judges an "Unknown" option; use pass@k (any success) and pass^k (all succeed; 75% per trial gives about 42% for 3); read transcripts to check failures are the agent's and not the grader's; near-0% usually means a broken task or grader; isolate each trial in a clean environment (STATED, [Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)).

Patterns across them (INFERENCE from the above):
- Tasks: real sites (WebVoyager, Online-Mind2Web) give realism but drift over time; self-hosted sites (WebArena) are stable and checkable. Our mock sites are the second kind.
- Scoring: either check final state/answer in code, or use an LLM judge calibrated to about 85% human agreement. Judges disagree enough that the judge itself needs a human-labelled check.
- Randomness: the sources I read mostly say it exists and hurts; only Anthropic's guidance gives a method (repeat trials, pass@k / pass^k). Browser Use does not report run counts.
- Failure categories: none of the pages I read give a reportable taxonomy. I could not verify any category list; read the full papers if we want one.

## What our test set should borrow

- Size and start: 20-50 tasks is enough to start (Anthropic). Build them from sites we control, as WebArena does, so answers do not drift.
- Known answers: one short, checkable answer per task (BrowseComp style: opening hours, price of a named service, earliest free slot, phone number), plus a reference solution proving each is solvable.
- Same task, three versions of the site: plain HTML, JS-rendered, and behind a booking form. Run each stand-in profile against all three. The score gap is the measurement of "legibility".
- Outcome grading in code first (exact match on answer or on form submission state); LLM judge only for free-text, with an "Unknown" option and a hand-checked sample.
- Repeat each task several times per profile; report pass@k and pass^k, not one run. Fresh environment per trial.
- Include negative tasks where the correct behaviour is "this business does not offer that" or "I cannot tell", so stand-ins are not rewarded for guessing.
- Read a sample of transcripts to separate stand-in mistakes from site or grader faults; treat near-zero results as a suspected broken task.
- Sanity-check the stand-ins themselves: log what a stand-in sends (UA, JS on/off, robots.txt respected) against the table above, and flag fields we could not verify (ChatGPT agent, Comet, Manus, Grok, Instinct UAs) as assumptions in the demo.
